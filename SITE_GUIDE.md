## Что реализовано

- Услуги, студия, мастера, фотографии работ, FAQ и контакты.
- Свои запись, база и админка; ссылок записи на DIKIDI нет.
- Выбор услуги, мастера, даты и свободного времени с шагом 30 минут.
- Проверка длительности процедуры, пересечений и повторной отправки.
- Статусы записей, фильтры и поиск, смены и выходные, редактирование услуг.
- Авторизация, CSRF, ограничение попыток, серверная проверка согласия.
- Виджет Яндекса после разрешения посетителя, управление этим разрешением в подвале.
- Локальные изображения и шрифты, черновики юридических страниц, запрет индексации.

## Локальная разработка

Нужны Node.js, совместимый с Vite 7 (например, Node 22.12+), npm и PHP 8.2 с `pdo_sqlite`, `sqlite3`, `mbstring`, `openssl`. Для тестов нужен Python 3.10+. На исходном компьютере PHP в PATH не был найден; установка PHP проектом не выполняется.

Из корня проекта:

```sh
npm ci
php server/app/install.php
```

Используйте lock-файл и `npm ci`, не обновляйте все зависимости без отдельной задачи. При первом запуске установщик создаёт мастеров, услуги и 14 дней демонстрационных смен. Повторная установка не продлевает расписание автоматически.

### Настройка администратора на новом окружении

Создайте приватный `server/app/.env` с собственным случайным паролем. Пример содержит только плейсхолдер:

```ini
ADMIN_USER="admin"
ADMIN_PASSWORD="{{GENERATE_UNIQUE_PASSWORD}}"
```

Выполните:

```sh
php server/app/credentials.php
```

Скрипт заменяет открытый пароль на `ADMIN_HASH` и устанавливает логин `admin`. Сохраните пароль отдельно в защищённом `.env`, не печатайте его в чат или логи. На исходном компьютере корневой `.env` содержит доступ, подготовленный для демонстрационного сайта. Он не входит в GitHub. На хостинге логин и хеш находятся в `app/.env`.

Смены пароля через кабинет пока нет. Для неё требуется отдельно обновить `.env` в нужном окружении и запустить `credentials.php`.

### Запуск двух процессов

Первый терминал из корня проекта:

```sh
php -S 127.0.0.1:8092 -t server server/app/router.php
```

Второй терминал:

```sh
npm run dev
```

Откройте http://127.0.0.1:5173/ и http://127.0.0.1:5173/admin/. Vite обслуживает интерфейс и передаёт `/api` PHP-серверу. Если услуги не загружаются, проверьте запуск PHP и наличие базы.

### Сборка

```sh
npm run build
```

В `dist/` появятся интерфейс, PHP API, кабинет, фотографии и шрифты. `.env` и каталоги `data` не копируются. `dist/` создаётся заново: не храните единственную копию базы или секретов внутри сборки.

Для локального просмотра полной сборки отдельно скопируйте тестовые `server/app/.env` и `server/app/data/` в соответствующие пути `dist/app/` и запустите:

```sh
php -S 127.0.0.1:8092 -t dist dist/app/router.php
```

`npm run preview` не исполняет PHP и не заменяет полный запуск.

## База и запись

На хостинге база расположена в `app/data/emblika.sqlite`, в репозиторий не входит.

| Таблица | Содержимое |
|---|---|
| `masters` | Мастера, направления и фото |
| `services` | Услуги, категории, цена, длительность, мастера и доступность |
| `shifts` | Рабочая смена мастера на конкретную дату |
| `appointments` | Записи, снимок услуги и цены, время, статус и согласие |
| `attempts` | Ограничение частоты запросов по хешу IP и действию |

Все расчёты времени — `Europe/Moscow`. Запись доступна не раньше чем через 30 минут, даты — в пределах 90 дней. Начала окон идут с шагом 30 минут, вся процедура должна помещаться в смену. Несколько процедур оформляются отдельными записями.

Статусы: `pending` — новая; `confirmed` — подтверждена; `completed` — завершена; `cancelled` — отменена. Любой статус кроме отменённого занимает время. Отмена освобождает окно. Восстановление отменённой записи запрещено, если оно создаст пересечение с другой записью.

Цена и длительность фиксируются в записи при создании. Изменение услуги не меняет уже созданные записи. Транзакция SQLite защищает от двойного бронирования, идентификатор запроса — от повторной отправки.

### Срок хранения и очистка

Тестовые записи удаляются через 30 дней **с момента создания**, даже если визит выбран на более позднюю дату. Это ограничение демоверсии; для рабочего запуска нужно согласовать другой срок или правила хранения.

Очистка запускается при загрузке каталога/кабинета и отдельным сценарием. Для ежедневной задачи, например в 03:15, в панели Timeweb используйте:

```sh
php /home/c/cc250576/emblema/public_html/app/maintenance.php
```

Настройка этой задачи не подтверждена. Не считайте планировщик подключённым без проверки панели. Через SSH `crontab` недоступен.

## Как пользоваться кабинетом

1. Войти на `/admin/` с отдельно выданными данными.
2. В «Записях» использовать поиск, фильтры даты и статуса. Обновление происходит раз в минуту; кнопка «Обновить» также сбрасывает фильтры.
3. Менять статусы. Удаление требует подтверждения и полностью стирает запись.
4. В «Расписании» выбрать мастера, дату, начало и конец смены с шагом 30 минут либо выходной. Закрыть смену с активной записью нельзя.
5. В «Услугах» менять название, цену, длительность и доступность.

Добавление новых мастеров, новых услуг, изменение категорий и связей мастеров через интерфейс не реализовано. Для этого нужна доработка или контролируемое изменение базы. Правка `install.php` не обновляет существующие строки автоматически.

## Публикация на Timeweb

**Каталог `/home/c/cc250576/public_html` относится к другому проекту. Не трогайте его.** Для «Эмблики» используется только `/home/c/cc250576/emblema/public_html`.

1. Проверить изменения, выполнить `npm ci` и `npm run build`.
2. Проверить отсутствие `.env`, базы и тестовых данных в `dist/`.
3. Сделать защищённую резервную копию текущего сайта и базы вне webroot. Базу копировать через SQLite backup API или при остановленных изменениях; обычное копирование в момент записи может дать несогласованную копию. Копия содержит секреты и не должна попадать в GitHub.
4. Создать архив сборки и передать его вне webroot:

```sh
tar -czf release.tar.gz -C dist .
scp release.tar.gz cc250576@vh470.timeweb.ru:/home/c/cc250576/emblema-release.tar.gz
```

5. По SSH распаковать в `/home/c/cc250576/emblema/public_html`. Архив не содержит рабочих `app/.env` и `app/data/`, они сохраняются. **Не копировать локальный `.env` поверх серверного.**
6. Установить права 755 на каталоги, 644 на файлы сборки и 600 на `app/.env`. Сохранить обе защиты `.htaccess`.
7. Запускать `php app/install.php` при первой установке или согласованном изменении схемы. Это не универсальная система миграций.
8. Проверить HTTPS, главную, кабинет, каталог, запись, фотографии, юридические страницы и запрет доступа к `app/`.

Распаковка не удаляет устаревшие файлы. Удаляйте только явно выявленные ненужные файлы после проверки путей. Не используйте массовую очистку каталога.

Резервная копия исходной заглушки: `/home/c/cc250576/emblema-before-20260926.tar.gz`. Она не заменяет свежую копию перед обновлением. Внешний `deploy-timeweb.sh`, упомянутый в личных заметках, на исходном компьютере по ожидаемому пути не найден.

PHP на Timeweb изолирован корнем сайта: секреты и база находятся внутри `public_html/app/`, закрытого `.htaccess` в самом каталоге и правилом в корне сайта. Перенос служебных файлов выше `public_html` сломает доступ PHP.

## Проверки перед передачей

```sh
npm run build
php -l server/api/index.php
php -l server/app/bootstrap.php
python scripts/test_api.py http://127.0.0.1:8092
```

Для Python-тестов нужен корневой `.env` с доступом **к отдельной тестовой базе**. Скрипт создаёт записи «Тест API», меняет статусы и удаляет их. Требует открытой смены через два дня, повторно сохраняет параметры услуги. Не запускайте его на клиентской рабочей базе.

Ранее на отдельном сервере прошли проверки: согласие, CSRF, авторизация, два запроса на одно время, повторная отправка, отмена/восстановление, запрет закрытия занятой смены, сохранение услуги, удаление и выход. На публичном домене подтверждались HTTPS 200, каталог API и отказ 403 для базы и `.env`.

Дополнительно проверяйте:

- мобильную страницу без горизонтальной прокрутки;
- запись через интерфейс, появление в кабинете и отмену;
- виджет после разрешения и отсутствие загрузки после отказа;
- отказ доступа к `/app/.env`, `/app/data/emblika.sqlite`, `/app/bootstrap.php`;
- перенаправление HTTP → HTTPS и Secure/HttpOnly/SameSite у cookie;
- отсутствие запрещённых CDN/счётчиков и внешней записи в исходниках;
- отсутствие секретов и базы в `git status`.

## Ограничения и следующий этап

- Реальный приём клиентов не включён; сохраняются предупреждения демоверсии.
- Сертификат HTTPS работал. Включение обязательного HTTP → HTTPS в панели не было подтверждено, его нужно проверить отдельно.
- Ежедневная задача очистки не подтверждена; реализована очистка по обращениям.
- Уведомлений, оплаты, личного кабинета клиента и самостоятельной отмены по ссылке нет.
- Расписание создаётся на 14 дней один раз, смены нужно продлевать через кабинет.
- Реквизиты оператора и документы требуют заполнения и проверки. До настоящих заявок нужно выполнить требования к обработке персональных данных, включая уведомление Роскомнадзора, когда оно требуется.
- Цены, длительности, услуги, расписание и фотографии должен подтвердить заказчик.
- Для рабочей версии отдельно снять запрет индексации и проверить метаданные.

GitHub хранит код и материалы сайта, но не состояние базы и не доступ администратора.
