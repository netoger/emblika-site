## Что реализовано

- Сайт разбит на вкладки (верхнее меню по просьбе заказчицы): «Услуги и комплексы», «Запись», «Отзывы», «О нас», «Обучение», «Контакты»; «Главная» открывается по логотипу. Адреса — `#/services`, `#/booking`, `#/reviews`, `#/about`, `#/training`, `#/contacts`; на сервере правила перезаписи не нужны. Прежние адреса (`#/prices`) и якоря вида `#team` перенаправляются на нужную вкладку.
- Пять направлений: ногти, ресницы и брови, эстетическая косметология (раздел «Уход за лицом» переименован), волосы, аппаратная коррекция фигуры.
- Блоки «Без скрытых доплат», «Подарочные сертификаты», «Кэшбэк 3%» — на главной и во вкладке услуг; те же сведения в частых вопросах.
- Услуга работает в одном из двух режимов: «онлайн-запись» (нужен хотя бы один мастер) или «только заявка» — тогда в прайсе кнопка «Оставить заявку», а в форме записи услуги нет. Новые процедуры (уход за волосами, чистка, пилинг, RF-лифтинг, коррекция фигуры) пока по заявке: цены, длительность и мастера не подтверждены.
- Фото у каждой услуги: загружается в кабинете, показывается в прайсе и открывается крупно.
- Блок «Комплексы и спецпредложения»: услуги из разделов «Комплексы» и «Спецпредложения» показываются карточками; пока их нет — заглушка с контактами.
- Заявка на аппаратную коррекцию фигуры (отдельная форма во вкладке услуг, тип `body`, номер `КФ-…`).
- «Обучение» по тексту студии: два формата (офлайн с нуля и онлайн-программа «Бьюти Масштаб»), карточки курсов, пять этапов, форма с выбором курса по группам. Кнопки у курсов и «Узнать о программе» подставляют курс в форму.
- Часы работы 10:00–20:00, два телефона, «Написать нам» — сообщения сообщества ВКонтакте и Telegram (MAX — после получения ссылки).
- Зелёная фирменная гамма, первый экран с фото студии, карточки направлений с ценой «от».
- Прайс с поиском и фильтром по направлениям; из любой строки можно перейти к записи или заявке.
- О нас и ценности, мастера, галерея работ и интерьера, FAQ.
- Заявка клиента «Подберём процедуру» и вкладка «Заявки» в кабинете: тип (клиент, обучение, коррекция фигуры), статус, фильтр по типу, удаление.
- Контакты: адрес, ориентир, часы работы, телефон, Telegram, ВКонтакте, маршрут и карта Яндекса после разрешения.
- Свои запись, база и админка; ссылок записи на DIKIDI нет.
- Выбор услуги, мастера, даты и свободного времени с шагом 30 минут.
- Проверка длительности процедуры, пересечений и повторной отправки.
- Статусы записей, фильтры и поиск, смены и выходные, редактирование услуг.

## Локальная разработка

Нужны Node.js, совместимый с Vite 7 (например, Node 22.12+), npm и PHP 8.2 с `pdo_sqlite`, `sqlite3`, `mbstring`, `openssl`. Для тестов нужен Python 3.10+. На исходном компьютере PHP в PATH нет; установка PHP проектом не выполняется. Без PHP интерфейс в `npm run dev` открывается, но каталог, запись и заявки отвечают ошибкой 500 — для них используйте временный стенд на сервере (см. «Проверки перед передачей»).

Если `npm` не запускается из средства предпросмотра из-за пробела в пути `C:\Program Files`, запускайте Vite напрямую: `node node_modules/vite/bin/vite.js --host 127.0.0.1 --port 5173 --strictPort`.

Из корня проекта:

```sh
npm ci
php server/app/install.php
```

Используйте lock-файл и `npm ci`, не обновляйте все зависимости без отдельной задачи. При первом запуске установщик создаёт мастеров, услуги и 14 дней демонстрационных смен. Повторная установка не продлевает расписание автоматически.

### Настройка администратора на новом окружении

Создайте приватный `server/app/.env` с собственным случайным паролем. Пример содержит только плейсхолдер:

```ini
ADMIN_USER="admin"
ADMIN_PASSWORD="{{GENERATE_UNIQUE_PASSWORD}}"
```

Выполните:

```sh
php server/app/credentials.php
```

Скрипт заменяет открытый пароль на `ADMIN_HASH` и устанавливает логин `admin`. Сохраните пароль отдельно в защищённом `.env`, не печатайте его в чат или логи. На исходном компьютере корневой `.env` содержит доступ, подготовленный для демонстрационного сайта. Он не входит в GitHub. На хостинге логин и хеш находятся в `app/.env`.

Смены пароля через кабинет пока нет. Для неё требуется отдельно обновить `.env` в нужном окружении и запустить `credentials.php`.

### Запуск двух процессов

Первый терминал из корня проекта:

```sh
php -S 127.0.0.1:8092 -t server server/app/router.php
```

Второй терминал:

```sh
npm run dev
```

Откройте http://127.0.0.1:5173/ и http://127.0.0.1:5173/admin/. Vite обслуживает интерфейс и передаёт `/api` PHP-серверу. Если услуги не загружаются, проверьте запуск PHP и наличие базы.

### Сборка

```sh
npm run build
```

В `dist/` появятся интерфейс, PHP API, кабинет, фотографии и шрифты. `.env` и каталоги `data` не копируются. `dist/` создаётся заново: не храните единственную копию базы или секретов внутри сборки.

Для локального просмотра полной сборки отдельно скопируйте тестовые `server/app/.env` и `server/app/data/` в соответствующие пути `dist/app/` и запустите:

```sh
php -S 127.0.0.1:8092 -t dist dist/app/router.php
```

`npm run preview` не исполняет PHP и не заменяет полный запуск.

## База и запись

На хостинге база расположена в `app/data/emblika.sqlite`, в репозиторий не входит.

| Таблица | Содержимое |
|---|---|
| `masters` | Мастера, направления и фото |
| `services` | Услуги, раздел, описание, цена, длительность, мастера, доступность, фото (`image`) и способ записи (`mode`: `booking` или `request`) |
| `shifts` | Рабочая смена мастера на конкретную дату |
| `appointments` | Записи, снимок услуги и цены, время, статус и согласие |
| `leads` | Заявки клиентов (`client`) и учеников (`training`): направление, имя, телефон, комментарий, статус, согласие |
| `attempts` | Ограничение частоты запросов по хешу IP и действию |

Таблица `leads` создаётся автоматически при первом обращении к базе, поэтому на уже работающем сайте повторно запускать `install.php` не нужно.

### Миграции

Изменения схемы выполняет `migrate()` в `bootstrap.php` по номеру `PRAGMA user_version` — сами, при первом обращении к базе после выкладки, в одной транзакции. Версия 1 (30.09.2026): поля `image` и `mode` у услуг, переименование «Уход за лицом» → «Эстетическая косметология», пять новых процедур в режиме заявки, продление будущих смен с 19:00 до 20:00. Проверено на базе, созданной прежней версией кода. Новую миграцию добавляйте следующим номером, не меняя уже выполненные.

### Фото услуг

Загружаются в кабинете и сохраняются в `public_html/uploads/services/` (вне `app/`, иначе `.htaccess` не отдаст их посетителям). Файл проверяется (JPG, PNG, WebP, не меньше 200×200), поворачивается по EXIF, уменьшается до 1200 точек и перекодируется в JPG — постороннее содержимое не сохраняется. Имя случайное. `uploads/.htaccess` создаётся автоматически и запрещает исполнение скриптов. Каталог не входит в Git и в архив выкладки: фото живут только на сервере и попадают в резервную копию сайта. Статусы заявок: `new` — новая, `contacted` — связались, `done` — закрыта. Заявка проверяет CSRF, согласие, телефон, скрытое поле от ботов, повторную отправку и ограничена 8 отправками в час с одного IP.

Все расчёты времени — `Europe/Moscow`. Запись доступна не раньше чем через 30 минут, даты — в пределах 90 дней. Начала окон идут с шагом 30 минут, вся процедура должна помещаться в смену. Несколько процедур оформляются отдельными записями.

Статусы: `pending` — новая; `confirmed` — подтверждена; `completed` — завершена; `cancelled` — отменена. Любой статус кроме отменённого занимает время. Отмена освобождает окно. Восстановление отменённой записи запрещено, если оно создаст пересечение с другой записью.

Цена и длительность фиксируются в записи при создании. Изменение услуги не меняет уже созданные записи. Транзакция SQLite защищает от двойного бронирования, идентификатор запроса — от повторной отправки.

### Срок хранения и очистка

Тестовые записи и заявки удаляются через 30 дней **с момента создания**, даже если визит выбран на более позднюю дату. Это ограничение демоверсии; для рабочего запуска нужно согласовать другой срок или правила хранения.

Очистка запускается при загрузке каталога/кабинета и отдельным сценарием. Для ежедневной задачи, например в 03:15, в панели Timeweb используйте:

```sh
php /home/c/cc250576/emblema/public_html/app/maintenance.php
```

Настройка этой задачи не подтверждена. Не считайте планировщик подключённым без проверки панели. Через SSH `crontab` недоступен.

## Как пользоваться кабинетом

1. Войти на `/admin/` с отдельно выданными данными.
2. В «Заявках» видны обращения клиентов, учеников и по коррекции фигуры. Позвоните по номеру, поменяйте статус, удалите заявку после обработки.
3. В «Записях» использовать поиск, фильтры даты и статуса. Обновление происходит раз в минуту; кнопка «Обновить» также сбрасывает фильтры.
4. Менять статусы. Удаление требует подтверждения и полностью стирает запись.
5. В «Расписании» выбрать мастера, дату, начало и конец смены с шагом 30 минут либо выходной. Закрыть смену с активной записью нельзя.
6. В «Услугах» — добавлять, менять и удалять услуги: название, раздел, описание, цена, длительность, мастера, способ записи, показ на сайте, фото. Изменения сразу видны в прайсе и в форме записи. Комплексы и акции — это услуги в разделах «Комплексы» и «Спецпредложения». Услугу, на которую есть записи, удалить нельзя — её снимают с публикации.

Добавление мастеров и правка текстов страниц (о нас, обучение, контакты) через кабинет не реализованы: тексты заданы в `src/main.jsx` и `src/Training.jsx`. Правка `install.php` не обновляет существующие строки автоматически.

Текст «О нас» — черновик: заказчица пришлёт свой. Тексты «Обучения» — от студии (30.09.2026); служебные пометки из присланного текста на страницу не вынесены, «Instagram» в тексте заменён на «соцсети», «beauty» — на «бьюти». Программы, даты, стоимость обучения и документы об окончании на сайте не указаны. Часы работы (10:00–20:00) и второй телефон — от заказчицы; ссылки на Telegram и ВКонтакте — из карточки DIKIDI.

Instagram и WhatsApp на сайт не выведены, хотя заказчица присылала ссылку на Instagram: это сервисы Meta, признанной в РФ экстремистской организацией, и по скиллу `russian_site` ссылки и значки таких сервисов со страниц убираются. Вернуть их можно только по решению заказчицы после консультации с юристом. Латинское название онлайн-программы («BEAUTY МАСШТАБ») заменено на «Бьюти Масштаб» по 168-ФЗ; латиницу можно вернуть, если название зарегистрировано как товарный знак.

Версия согласия (`CONSENT_VERSION` в `server/app/bootstrap.php`) — `demo-2026-09-30`: тексты политики и согласия дополнены заявкой на коррекцию фигуры.

После отказа iframe не создаётся. Разрешение хранится в браузере под ключом `emblika-external`, меняется из подвала. Отзывы не копируются в SQLite; их состав и обновление зависят от Яндекса. Ссылка на карточку остаётся запасным способом просмотра.

Полную загрузку содержимого виджета на публичной версии ещё нужно проверить: раньше было подтверждено создание iframe, но не появление отзывов внутри него.

## Публикация на Timeweb

Быстрый путь с Windows: из корня проекта выполнить `powershell -ExecutionPolicy Bypass -File scripts\deploy.ps1` (если коммит уже сделан вручную — с ключом `-SkipGit`). Скрипт собирает сайт, проверяет, что в `dist/` нет `.env` и базы, делает резервную копию сайта и базы в `~/backups` на сервере, выкладывает архив, выставляет права, проверяет HTTPS, API и закрытость `app/`, затем коммитит и отправляет изменения на GitHub (перед коммитом отменяет его, если в нём оказались `.env`, база или архив). Ключи `-SkipHosting` и `-SkipGit` запускают только одну часть. Команды на сервер скрипт передаёт в base64: при обычной передаче через конвейер PowerShell 5.1 дописывает BOM, и bash не узнаёт первую команду. Ниже — те же шаги вручную.

**Каталог `/home/c/cc250576/public_html` относится к другому проекту. Не трогайте его.** Для «Эмблики» используется только `/home/c/cc250576/emblema/public_html`.

1. Проверить изменения, выполнить `npm ci` и `npm run build`.
2. Проверить отсутствие `.env`, базы и тестовых данных в `dist/`.
3. Сделать защищённую резервную копию текущего сайта и базы вне webroot. Базу копировать через SQLite backup API или при остановленных изменениях; обычное копирование в момент записи может дать несогласованную копию. Копия содержит секреты и не должна попадать в GitHub.
4. Создать архив сборки и передать его вне webroot:

5. По SSH распаковать в `/home/c/cc250576/emblema/public_html`. Архив не содержит рабочих `app/.env` и `app/data/`, они сохраняются. **Не копировать локальный `.env` поверх серверного.**

### Временный стенд на сервере

Когда локального PHP нет, API проверяют на Timeweb во временном каталоге вне сайта. PHP CLI и Python 3.10 там есть, а проброс портов по SSH запрещён — поэтому тесты запускаются на самом сервере:

1. Собрать `dist/`, упаковать без `.env` и `data`, передать архив и `scripts/test_api.py` в `~/emblika-test`.
2. Создать `site/app/.env` со случайным паролем, сгенерированным на сервере, и такой же `.env` рядом с тестом; выполнить `credentials.php` и `install.php` — получится отдельная база.
3. Запустить `php -S 127.0.0.1:<случайный порт> -t site site/app/router.php` в фоне, выполнить `python3 test_api.py http://127.0.0.1:<порт>`, остановить сервер.
4. Удалить `~/emblika-test` целиком. Пароль стенда никуда не выводится.

## Ограничения и следующий этап

- Реальный приём клиентов не включён; сохраняются предупреждения демоверсии.
- Переадресации HTTP → HTTPS нет: 29.09.2026 `http://emblema.tw1.ru/` отвечал 200. Через формы идут имена и телефоны, поэтому её нужно включить — в панели Timeweb или правилом в `.htaccess`. Правило проверять сразу после выкладки: при неверном условии сайт уходит в бесконечную переадресацию.
- На сервере работает `php -S 127.0.0.1:8092 app/router.php`, запущенный в одной из прошлых сессий. Если он не нужен, его можно остановить.
- Ежедневная задача очистки не подтверждена; реализована очистка по обращениям.
- Уведомлений, оплаты, личного кабинета клиента и самостоятельной отмены по ссылке нет.
- Расписание создаётся на 14 дней один раз, смены нужно продлевать через кабинет.
- Реквизиты оператора и документы требуют заполнения и проверки. До настоящих заявок нужно выполнить требования к обработке персональных данных, включая уведомление Роскомнадзора, когда оно требуется.
- Цены, длительности, услуги, расписание и фотографии должен подтвердить заказчик.
- Для рабочей версии отдельно снять запрет индексации и проверить метаданные.

GitHub хранит код и материалы сайта, но не состояние базы и не доступ администратора.
