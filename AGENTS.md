# Работа с проектом «Эмблика»

Перед изменениями прочитай `SITE_GUIDE.md` и актуальные исходники. Бренд — «Эмблика», домен `emblema.tw1.ru` указан намеренно. Это тестовый сайт для заказчика.

## Правила изменений

- Общайся, пиши комментарии и сообщения коммитов на русском.
- Для изменений сайта применяй доступный скилл `russian_site`.
- Не возвращай DIKIDI в сценарий записи и декоративную нумерацию разделов: пользователь явно попросил убрать их.
- Верхнее меню задано заказчицей: «Услуги и комплексы», «Запись», «Отзывы», «О нас», «Обучение», «Контакты». Instagram и другие сервисы Meta не выводи без её решения после консультации с юристом.
- Сохраняй React/Vite/Astryx + PHP/SQLite, локальные шрифты и фотографии. Не добавляй зависимости без необходимости.
- Не снимай отметки демоверсии и запрет индексации без поручения перейти к реальному запуску. Не придумывай реквизиты, отзывы, цены, лицензии и расписание.
- Секреты только в `.env`; не печатай пароли, хеши или токены в сообщения и логи. Не коммить базу, заявки, резервные копии и архивы.
- Перед изменениями проверяй `git status` и текущую ветку, сохраняй изменения пользователя.
- Виджет Яндекса загружай только после разрешения. Сохраняй возможность отозвать разрешение. Данные посетителей не отправляй в сторонние сервисы.

## Проверки

- Исходники интерфейса: `src/`; PHP: `server/`; ресурсы: `public/`.
- `dist/` создаётся через `npm run build`. Не исправляй только сборку.
- Для интерфейса проверяй сборку, мобильную ширину и основные действия.
- Для записи проверяй CSRF, согласие на сервере, авторизацию, пересечение времени, повторную отправку и отмену.
- `scripts/test_api.py` создаёт и удаляет синтетические записи. Используй отдельную тестовую базу. Локального PHP нет — запускай тесты на временном стенде `~/emblika-test` на сервере и удаляй его после (порядок в `SITE_GUIDE.md`).
- Не называй проверку успешной без результата. Отмечай незавершённое отдельно.
